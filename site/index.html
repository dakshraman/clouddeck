Security model

The web app never runs as root.

Most control panels put a root process behind a web login. CloudDeck splits the job in two: a small unprivileged panel for the browser, and a small privileged agent that only accepts typed operations.

Least privilege by design

The Next.js panel holds no system privileges. Only the Go agent runs as root, bound to 127.0.0.1:9090.

Typed commands, no shell

Every external command runs through an explicit argument array. Callers cannot inject shell strings — there is no sh -c.

Audit everything

Every mutation is appended to a JSONL audit log with timestamp, action, params, and outcome. Tasks keep their own live logs.

Path-confined by default

Domains are validated before any filesystem path is derived. The file manager stays inside the site webroot and rejects symlink escapes.

Install

Fresh VPS to running panel
in one command.

On Debian or Ubuntu the installer also provisions the host stack. On other distros it installs the panel and agent, and you bring the stack.

Root access on a fresh Linux server — x86_64 or arm64. The installer uses systemd when available, otherwise plain init scripts.

terminal
$ curl -fsSL https://github.com/dakshraman/clouddeck/releases/latest/download/install.sh | sudo bash
Installs to /opt/clouddeck. State lives in /var/lib/clouddeck, config in /etc/clouddeck. The admin account is created in the browser on first visit.
Installer flags
--version vX.Y.Z pin a release --panel-port 2083 panel port --prefix DIR install directory --no-panel agent only --no-agent panel only --uninstall --purge remove everything

A self-contained development stack: panel, agent, and nginx in containers. Good for a demo or a local evaluation.

compose
$ git clone https://github.com/dakshraman/clouddeck.git
$ cd clouddeck
$ docker compose up -d --build
Open http://localhost:2083. Sites are served on :8080; the agent is published on :9090 for development only. Keep it on localhost in production.

Run the panel on any OS with Node 20+, and the agent in dry-run mode without root or nginx.

$ cd panel
$ npm install
$ npm run dev        # http://localhost:2083

# agent, no root needed:
$ cd agent

Dry-run writes rendered nginx configs to agent/data/dryrun/ instead of touching the system. Requires Go 1.23+.

What Linux distributions are supported?

The one-command installer fully provisions Debian and Ubuntu, including nginx, PHP-FPM, MariaDB, certbot, and Node. On other distros the panel and agent still install, but you install the web stack yourself. The agent targets Linux with systemd, with a plain-init fallback.

Does the panel run as root?

No. The browser-facing Next.js panel is unprivileged. The small Go agent is the only privileged process, and it binds to 127.0.0.1:9090 by default. It accepts typed parameters, never shell strings, and audits every mutation.

Can I host Node, Python, Go, and Ruby apps?

Yes. CloudDeck detects installed runtimes and offers version pickers. Each app gets a supervised process, an automatically allocated local port, and an nginx reverse proxy. systemd is the default supervisor; PM2 and supervisord are selectable.

Is email deliverability guaranteed?

No. CloudDeck manages the mail software — Postfix, Dovecot, quotas, forwarders, autoresponders, DKIM, and DNS records. Deliverability still depends on your IP reputation, reverse DNS, MX setup, and sending behavior. CloudDeck does not run an outbound relay.

Can I try it without a server?

Yes. The Docker Compose stack runs the panel, agent, and nginx locally. Or run the agent with AGENT_DRY_RUN=true — it renders nginx configs to disk without changing the system, so it works on any OS.

How do updates work?

The installer adds a clouddeck CLI. Run sudo clouddeck update to upgrade to the latest release, sudo clouddeck reinstall to re-download the current version, or clouddeck status to check the panel and agent.
